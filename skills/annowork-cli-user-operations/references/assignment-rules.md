# アサインの条件と注意事項

## 使用するコマンド
アサインする際は様々な情報を参照して、適切なアサインを決めます。その際、以下のコマンドが役立ちます。

* 予定稼働時間と比較する：`schedule list_workload_*`
* 実績作業時間とアサイン時間の累積時間を出力する：`schedule_actual list_*`


## 基本方針
ユーザーから特に指定がなければ、以下の条件を満たしてアサインしてください。一時的に条件が満たされないのは問題ありません。最終的なアサイン結果で満たされるようにしてください。

* メンバーのアサイン時間が予定稼働時間以下である
* 予定稼働時間の100%でアサインする。指定された時間に厳密に合わせるために、時間を指定してアサインしない。
* ユーザーからアサイン時間を指定されたら、原則その時間を超えるようにアサインする。予定稼働時間を下回って作業することはあっても、予定稼働時間を超えて作業することは基本ないため。


## アサイン時間の誤差

### 日ごとのアサイン時間
メンバー1人当たりの平均の予定稼働時間程度であれば、誤差の範囲内です。
たとえば「日ごとのアサイン時間を40時間にしてください」というユーザーからの指示に対して、メンバーの平均の予定稼働時間が4時間ならば、「日ごとのアサイン時間が42時間」でも問題ありません。

### ある期間内でのアサイン時間の合計
日ごとのアサイン時間程度であれば、誤差の範囲内です。
たとえば「10月のアサイン時間の合計を400時間にしてください」というユーザーからの指示に対して、日ごとのアサイン時間が20時間ならば、「10月のアサイン時間の合計が410時間」でも問題ありません。


## アサインする際の考慮事項
以下に、アサインする際に考慮することの例を示します。
どのようにアサインすればよいか分からなければ、以下のような内容をユーザーに質問してください。

* 実績作業時間とアサイン時間の合計（`schedule_actual list_daily`の結果）が、parent_jobの目標時間に達するか
* ある日付までの実績作業時間とアサイン時間の合計が、ジョブの要件を満たしているか
* ある期間内でのアサイン時間の合計が、ジョブの要件を満たしているか
* 日ごとアサイン時間が、ジョブの要件を満たしているか
* アサインされているメンバー数が、ジョブの要件を満たしているか
* アサインされているメンバーの構成
    * 初級アノテータだけで構成されていないか
    * 上級アノテータだけで構成されていないか
    * 受入作業ができる人もアサインされているか
